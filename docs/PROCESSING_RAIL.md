# The Processing rail

The rail on the right of the window shows how the data you are looking at was
made, step by step, for an `afni_proc.py` run, and how healthy each step looks.
It is an application service (`src/processing/`), not an `afni-core` algorithm.

## Opening a run

afniru looks for a run when it starts and when you ask. It only looks in the
places below, and never searches parent trees.

| Where | What is used |
|---|---|
| a directory containing `proc.<subj>` (a script whose first lines say `auto-generated by afni_proc.py`) | that script; the results are the `output_dir` the script names, inside that directory |
| a directory named `<subj>.results` | `proc.<subj>` next to it (or a `proc.*` script inside it) |

Directories tried, in order:

1. directories given on the command line (`afniru path/to/sub-01.results`); a
   failure is shown in the status bar,
2. the current working directory, and the folders of the files given on the
   command line (failures are silent),
3. **File ▸ Open results directory…**, or dropping a directory on the window.

A run whose results directory does not exist yet loads with every step
*Unknown* and a note, so you can open a pipeline before it runs.

## What is read

| Input | Used for |
|---|---|
| `proc.<subj>` script | the **executed order** (the `# ==== name ====` banners, in file order), each block's outputs, the run list, the subject, the generating command |
| the results directory | whether each output exists; dataset headers |
| `out.ss_review.<subj>.txt` | Dice and degrees-of-freedom and censor-fraction values (lines `label : value`) |
| `out.pre_ss_warn.txt`, `out.4095_warn.txt`, `out.cormat_warn.txt` | AFNI's own warnings |

**Steps.** Every banner is a step except `setup`, `finalize`, `QC_review` and
`blur estimation`, which do no data processing. Known blocks get friendly
names (`tcat` Inputs, `outcount` Outlier check, `tshift` Slice timing, `volreg`
Motion correction, `align` Alignment, `tlrc` Template warp, `blur` Smoothing,
`mask` Masks, `scale` Scaling, `regress` Regression). Unknown blocks keep their
own name; a block that appears twice becomes `name` and `name (2)`; omitted
blocks are simply absent; the order is the script's, not a fixed pipeline.

**Artifacts.** Outputs are found from `-prefix`, `-bucket`, `-cbucket`,
`-errts`, `-fitts`, `-Rbuck`, `-Rerrts`, `-Rfitts`, `-x1D`, `-xjpeg`, `-write*`,
`3dcopy` destinations, `> file` and `| tee file`, plus the outputs
`align_epi_anat.py` names from `-anat` and `-suffix` (`<anat><suffix>`, its
`_mat.aff12.1D`, and `<anat>_ns` with `-save_skullstrip`). `$subj` and `$run`
are filled in (one artifact per run). Temporaries (`rm.*`) are ignored.
Each artifact records its role (anatomy, EPI, mask, stats, residuals,
transform, motion, censor, regressors, report), space (orig/acpc/tlrc, from the
view), whether it exists, whether `afni-io` can open an AFNI header and BRIK,
the grid size, and the script line that writes it. A name written by two steps
(for example `anat_ns`, first in the subject's space and then in the
template's) resolves to the later view in the later step.

NIfTI outputs are checked for existence only; they are not read in full.

## Health

Health is **Good**, **Caution**, **Failed** or **Unknown**. A step's state is
the **worst** of its checks, in that order; Unknown ranks below Caution and above
Good, so a missing measurement is never shown as Good and a failed check is
never hidden by passing ones. Every check stays available in the detail window
with its finding, rule and source.

Where AFNI raises a warning itself, afniru reports exactly that. The numeric
limits are **afniru defaults**, chosen from AFNI's own review guidance; they
are not AFNI standards, and each is stated in the check's rule text.

| Check id | Step | Source | Good | Caution | Failed | Unknown |
|---|---|---|---|---|---|---|
| `outputs.present` | any with outputs | files in the results directory | all outputs exist | – | an output is missing although a later step wrote output | outputs missing and nothing later exists (not run yet or still running) |
| `outputs.readable` | any with AFNI datasets | `.HEAD` + BRIK read by `afni-io` | all open | – | one cannot be opened | – (NIfTI is not checked) |
| `grid.runs` | any with ≥2 EPI datasets | `DATASET_DIMENSIONS` of each | same size | – | sizes differ | – |
| `inputs.pre_steady_state` | Inputs | `out.pre_ss_warn.txt` | file empty | any warning | – | file missing |
| `inputs.saturation_4095` | Inputs | `out.4095_warn.txt` | file empty | any warning | – | file missing |
| `align.mask_dice` | Alignment | review: `anat/EPI mask Dice coef` | ≥ 0.80 | 0.50 – 0.80 | < 0.50 | value missing |
| `warp.mask_dice` | Template warp | review: `anat/templ mask Dice coef` | ≥ 0.80 | 0.50 – 0.80 | < 0.50 | value missing |
| `regress.dof_left` | Regression | review: `degrees of freedom left` | ≥ 50 | 1 – 49 | ≤ 0 | value missing |
| `regress.censor_fraction` | Regression | review: `censor fraction` | ≤ 0.10 | 0.10 – 0.30 | > 0.30 | value missing |
| `regress.cormat_warnings` | Regression | `out.cormat_warn.txt` | file empty | any warning | – | file missing |

A step with no outputs and no measurement gets one Unknown check
(`none`) that says so.

Thresholds live as constants at the top of `src/processing/health.rs`.

## The rail

- Steps run top to bottom as a subway line. A **blue node with a ring** is the
  selected step; **gray nodes** are the rest. Selection and health are
  independent.
- The pill at the far right shows health with an icon (✓ good, ⚠ caution, ✕
  failed, ? unknown), a tooltip, and a screen-reader label like
  `Alignment, Caution`.
- Selecting a step shows one reason line and `N datasets · View`; ⓘ opens a
  window with every check (finding, rule, source) and every file (role, space,
  missing or unopenable).
- **View** asks which dataset to show: the step's outputs, and the earlier
  output of the same kind for before/after comparison. Choosing one replaces
  the underlay (the dialog says so). The crosshair keeps its place in world
  coordinates when the new grid covers it, otherwise it goes to the center. Two
  controllers (A/B) will later make side-by-side comparison possible.
- About 15% of the window width; drag to resize; `»` collapses it to a strip
  with one health dot per step. Below 1000 points of window width it is always
  a strip and opens as a drawer.
- Keyboard: Tab to the list, ↑ ↓ move, Enter selects. The ⓘ in the header is
  the legend.
- **Refresh**: ⟳ reloads from disk, and the run is checked for changed files
  every 2 seconds. The selected step stays selected, and the displayed dataset
  is never changed by a refresh.

## Tests and fixtures

`tests/fixtures/processing/<case>/proc.sub-01` are real `afni_proc.py` scripts
(regenerate with `make_fixtures.sh`, which needs AFNI): `complete`, `two_runs`,
`omitted` (blocks left out) and `custom_order`. Result directories are built
at test time (`discover::testkit`): a tiny dataset or file for every output
the script declares, so tests can remove outputs, truncate runs, corrupt
headers and mismatch grids. Malformed, truncated and not-from-afni_proc
scripts are tests in `script.rs` and `discover.rs`. `egui_kittest` snapshots
cover the rail (all four states, selected, light, collapsed strip, narrow
drawer, detail window, long and custom labels) and the full shell.

## Not covered

- `afni_proc.py` options (for example `-regress_censor_motion`) are not yet
  used as evidence; the check sources are the script's commands and AFNI's
  outputs.
- One review file is used (the subject's own, or the only one present); the QC HTML (`QC_<subj>/`) is not read.
- The review and warning file formats follow AFNI's documentation and generator source; they have not been checked against a full real run on the development machine.
- Other pipelines (fMRIPrep, custom scripts) would be another adapter next to
  `processing/script.rs`.
